# Case: websqli-webshell-pivot

小さなEコマース小売業者の一般公開されている注文照会Webアプリケーションが、
自動化されたSQLインジェクションツールによってスキャンされた後、スキャンの
他のどのプローブも取得できなかったデータを返す1件のリクエストによって
実際に悪用される。攻撃者はWebシェルを設置し、それを通じて基本的な偵察を
行った後、Webサーバーから内部ファイルサーバーへピボットする — このホスト
への接続は、ファイアウォールのポリシー上は技術的に許可されている(古い
例外設定が失効せずに残っていた)が、業務上そのホストがそのような通信を
行う正当な理由は一切ない。このケースは特に、エージェントがWebサーバーを
本当の標的ではなく踏み台として認識できるか、「ファイアウォールが許可して
いた」ことと「このホストにとってこの通信が正常である」ことを区別できるか
を試す。

**評価対象のエージェントへ:** ここではなく、まず [AGENTS.md](AGENTS.md) を
開いてください。
