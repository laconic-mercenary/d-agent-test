# Case: credential-spray-domain-compromise

小さなエンジニアリング会社のドメインが、1つの一般社員のアカウントに対して
成功したクレデンシャルスプレー攻撃によって侵害される — しかし、実際に
長く続く被害は、攻撃者がその過程で昇格した、まったく別の過剰な権限を持つ
サービスアカウントを通じて発生する。このケースは特に、エージェントが
「攻撃者がどこから侵入したか」と「最終的に何が侵害されたか」を正しく
切り分けられるか、それとも最初にスプレーされたアカウントに、その後起きた
すべての結果を紐づけてしまうかを試す。

**評価対象のエージェントへ:** ここではなく、まず [AGENTS.md](AGENTS.md) を
開いてください。
