# Changelog — pth-lateral-logclear

## 1.0 — 2026-08-28

- Initial case build, generated synthetically for this project.
- `ENVIRONMENT.md` is human-authored; it documents the shared
  local-admin account's intended (local-only) purpose, its separate
  legitimate automated use by infrastructure processes, and a note
  about why network-traffic volume alone isn't a useful signal here —
  all load-bearing for Q2/Q3.
- **A real engine-behavior finding, worth documenting for future
  cases:** this engine version's `AuthenticationPackageName` selection
  for network logons (Event ID 4624, Logon Type 3) is a fixed 70/30
  Kerberos/NTLM random roll, entirely independent of whether the
  account is domain- or local-scoped. The original design for this
  case assumed a local (non-domain) account would reliably render as
  NTLM, distinguishing it from Kerberos-authenticated legitimate
  domain-admin traffic — confirmed false by direct inspection of the
  engine source and the rendered data (of the six attacker logon
  events, only one rendered as NTLM; the rest rendered as Kerberos,
  the same mix a legitimate domain admin's own baseline traffic
  shows). The case was redesigned around what the data *does* support
  reliably: the account's identity and cross-host/timing pattern, not
  its authentication protocol. See the paired generator README for
  full detail.
- **A second real finding:** the `log_cleared` event does not actually
  remove any preceding events from the affected host's own rendered
  log — it is purely additive (adds an Event ID 1102 record without
  suppressing anything before it). Confirmed directly: `FS-02`'s own
  log still contains both of the attacker's 4624 logon events after
  the 1102 event. Rather than design around a false "evidence is now
  gone" premise, Q5 tests whether the agent-under-test actually
  verifies this rather than assuming it.
- **A third, unplanned but well-suited finding**, discovered by
  inspecting the rendered data directly: the shared local-admin
  account also appears in several Event ID 4648 records generated by
  the environment's own baseline realism — legitimate, SYSTEM-context
  automated processes (a monitoring agent, a scheduled-task helper, a
  maintenance script) using the account's credentials between file
  servers, always sourced from another file server's own IP, never
  from the compromised workstation. Built into Q2 as a genuine
  discrimination test, the same pattern as `credential-spray-domain-compromise`'s
  `svc-sql`/`taskhostw.exe` baseline noise.
- Every fact in `EXAM.md`/the paired answer key was independently
  verified against the raw generated data before being written down.
