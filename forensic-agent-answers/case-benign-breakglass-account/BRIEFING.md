## The story, stage by stage

All timestamps UTC.

### Occasion 1 — night of Sept 3 (`APP-01` → `DB-01`)
**2024-09-03T07:14:35Z** — Event ID 4624, `svc-breakglass`, Logon Type
10 (RDP), source `10.90.10.31` (`WS-MOYELARAN-01`, Marcus Oyelaran's
workstation), on `APP-01`. **07:14:40Z** — PowerShell:
`Get-Service | Where-Object {$_.Status -ne 'Running'}`. **07:30:15Z**

session, no fresh RDP hop): PowerShell `Get-EventLog -LogName

occasion.

### Occasion 2 — night of Sept 4 (`FILE-01` → `DC-01`)
**2024-09-04T07:14:28Z** — Event ID 4624, `svc-breakglass`, Logon Type
10 (RDP), source `10.90.10.32` (`WS-DWHITFIELD-01`, Dana Whitfield's

**Q1's expected grouping: two distinct occasions, ~24 hours apart, each
touching two hosts** — not four independent unrelated logons, and not
one continuous session.

### The unrelated distractor (Q3)
**2024-09-04T04:00:08Z** — `rosa.delgado`, `WS-RDELGADO-01`, launches
`EXCEL.EXE ... MonthEnd_Report.xlsx`. This falls chronologically
between the two `svc-breakglass` occasions and is also technically
"off-hours" — but it's a different account, a different host, no
admin/diagnostic tooling involved, and per `ENVIRONMENT.md`, Rosa is in
Accounting with no on-call/IT role at all. It should be evaluated
entirely on its own: an ordinary employee doing ordinary (if
late-timed) work for a documented business reason (month-end
reporting), not folded into "more off-hours activity = more
suspicious."

## What would actually make this suspicious (Q4)

Concrete things that would flip the conclusion, none of which are
present here: (1) `svc-breakglass` used from a source **other than**
Marcus's or Dana's own workstation IPs; (2) commands beyond routine
diagnostics — account creation, group membership changes, data
staging/archiving, outbound network connections to unfamiliar
destinations; (3) usage with no correlating alert/trigger context, or
at a volume/frequency inconsistent with "occasional off-hours
response"; (4) any use of the account by a third identity not
documented as part of the on-call rotation.

## The core distinction the exam tests

This mirrors `ssh-shared-key-overlap`'s philosophy directly: the test
is proportionate judgment, not technical depth. An answer that flags
this as an incident because it pattern-matches "shared account +
off-hours + PowerShell" has failed the same way an answer that waves
off Rosa's late Excel session as automatically fine (without
independently confirming it isn't IT-related) would have failed in
the opposite direction. Both failure modes are graded.

to `DB-01:1433` a few seconds after launch — an ordinary data
connection for the report, further supporting (not undermining) that
this event is unrelated to `svc-breakglass`.
